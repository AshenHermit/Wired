# Version Pin 0.5.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pin the application version at `0.5.0` in every manifest, make the versioning convention explicit, and mark the state with a git tag.

**Architecture:** Pure bookkeeping: the four workspace `package.json` `version` fields are unified at the value the devlog already records (`0.5.0`), the convention is documented in `AGENTS.md` and the devlog template, and the result is committed and tagged `v0.5.0` on the current branch `v0.2.x`.

**Tech Stack:** JSON package manifests, Markdown docs, annotated git tags.

**Spec:** Approved in conversation (2026-11-13): the app is semantically 0.x (DB_SYNC-driven schema, no codegen, legacy room types alive), so no `1.0.0` promise; the devlog's latest `version` front matter (`0.5.0`, entries 2026-11-13) is the authoritative value; branch naming `v0.2.x` is stale and stays as-is.

## Global Constraints

- Exact value `0.5.0` in all four `package.json` files.
- Conventional Commits; this change is `chore:`.
- Do not touch `pnpm-lock.yaml`: workspace `version` fields are not dependency specs and never affect the lockfile.
- Language: `AGENTS.md` is English; `frontend/content/devlog/_template.md` is Russian — match each file.
- The tag must be annotated and must point at the commit that pins the versions.
- Nothing is pushed; the user decides when to push.

## Review Focus

- **Missed manifest:** all four `package.json` (root, `packages/server`, `packages/shared`, `frontend`) must move together; a missed one leaves the split sources of truth this change removes.
- **Runtime consumers:** nothing reads these fields today (grep found only `127.0.0.1` IP matches), so no test cycle applies; verification is the commands below.
- **Tag placement:** `v0.5.0` must point at the pinning commit, not the pre-change HEAD (`50f0043`).
- **Content validation:** `_template.md` is skipped by `listMarkdownFiles` (`!name.startsWith('_')` in `frontend/src/lib/content.ts:151`), so edits there cannot break `validate:content`; still run it as a cheap guard.
