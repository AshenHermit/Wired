# Теги пакета: ввод чипами с подсказками из workshop

Дата: 2026-11-03
Статус: proposal

Дополняет `2026-11-03-package-metadata-and-slug-editing-design.md` (§7.2, строка
«Теги»): свободный ввод через `parseTags` заменяется полем с чипами и
подсказками. Формат хранения и серверная валидация не меняются.

## 1. Интент

Теги — свободные токены `[a-z0-9_-]{1,32}`, до 10 штук, `jsonb string[]` с
нормализацией в `package-tags.ts`. Их уже ищет `GET /workshop?q=` (ILIKE по
`jsonb_array_elements_text`), но при редактировании пользователь вводит их
вслепую строкой `"gameplay, hero"` и не видит, какие теги уже приняты в
каталоге. Нужно: ввод чипами и подсказки существующих тегов **только из
опубликованных пакетов workshop** (решение пользователя).

Цель — меньше рассинхрона тегов («2d» vs «2D» vs «2-d»), меньше опечаток,
и ввод без запоминания формата.

## 2. Goals

- Поле «Теги» в диалоге «Редактировать пакет»: чипы, добавление/удаление,
  Enter и запятая коммитят, Backspace на пустом вводе удаляет последний чип.
- Подсказки: существующие теги workshop с частотой, фильтр по подстроке
  локально, выбор мышью и с клавиатуры.
- Свободный ввод сохранён: «Создать „foo“» добавляет новый валидный тег.
- Клиентская валидация зеркалит серверную, `invalid_tags` остаётся страховкой.
- Один новый публичный эндпоинт со списком тегов workshop.

## 3. Non-goals

- Поиск/фильтр по тегам в каталоге (отдельная задача; сейчас работает `?q=`).
- Переименование, слияние и модерация тегов; админ-таксономия.
- Подсказки из приватных пакетов комнат.
- GIN-индекс на `scripting_package.tags` — при текущих объёмах не нужен,
  добавим, когда каталог вырастет (см. §8).
- Изменение формата хранения или DTO.

## 4. Anti-goals

- Вторая реализация правил тега на клиенте, расходящаяся с сервером.
- Блокирующая ошибка подсказок: если список не загрузился, поле обязано
  продолжать работать как свободный ввод.
- Терять набранный текст при сохранении формы.

## 5. Approaches

| Вариант | Что даёт | Чем платим |
|---|---|---|
| A. Официальный shadcn `combobox` с чипами | Готовая a11y-логика | Новая зависимость `@base-ui/react` — второй headless-слой рядом с `radix-ui`; «создать новый тег» всё равно дописывать |
| B. Community (`emblor` v1, 21st.dev) | Быстрый старт | React 18 peer, `cmdk@0.2`, чужие радикс-пакеты, порт под Tailwind v4; автокомплит в v2 вырезан |
| **C. Свой `TagInput` на существующих примитивах** (выбрано) | Ноль новых зависимостей, стиль и тесты как у остальных компонентов, полный контроль над подсказками | Клавиатуру и ARIA пишем сами (~120 строк) |

## 6. Design

### 6.1. API: `GET /scripting-packages/workshop/tags`

Публичный, как `GET /workshop`, объявляется в контроллере **до** `@Get(':id')`
(рядом с `workshop/lookup`).

```
GET /scripting-packages/workshop/tags?q=&limit=&offset=
→ { items: { tag: string; count: number }[], total: number }
```

- Выборка идёт по тем же строкам, что и каталог: `p."roomId" IS NULL` и
  `JOIN LATERAL` на последнюю опубликованную ревизию (`WORKSHOP_SELECT`),
  иначе подсказка могла бы предложить тег, которого в каталоге не видно.
- SQL: `CROSS JOIN LATERAL jsonb_array_elements_text(p.tags)` → `GROUP BY t.tag`,
  `COUNT(*)::int AS count`, `ORDER BY count DESC, t.tag ASC`,
  `COUNT(*) OVER() AS total` (окно считается после группировки, как `total`
  в `LIST_SQL`).
- `q` нормализуется как в `list()`: trim → lowercase → slice(64), матч
  `t.tag ILIKE '%q%'`. `limit` по умолчанию 100, зажимается в 1..200;
  `offset` ≥ 0. Нечисловые/дробные значения отсекаются до запроса
  (как в `list()`).
- Типы в `packages/shared/src/api/types.ts`: `WorkshopTagCount`,
  `WorkshopTagListing`; сервис `PackageWorkshopService.tags()`.

### 6.2. Компонент `TagInput`

`frontend/src/components/packages/tag-input.tsx`, клиентский, без новых
зависимостей.

Пропсы: `id?`, `value: string[]`, `onChange(next: string[])`,
`disabled?`, `max = 10`, `placeholder?`.

Поведение:

- Чипы и `<input>` в одной рамке (`rounded-md border border-input
  focus-within:ring-…`), чипы — как существующие бейджи в
  `workshop-browser.tsx`; у каждого чипа кнопка с `aria-label`
  «Удалить тег <tag>».
- Коммит: Enter и `,`; на пустом вводе Backspace удаляет последний чип.
  Draft нормализуется на клиенте: trim → lowercase → `^[a-z0-9_-]{1,32}$`,
  дедуп, лимит `max`. Невалидный draft остаётся в поле, рамка краснеет и
  показывается подсказка формата; в `value` он не попадает.
- Blur коммитит валидный draft: пользователь может набрать тег и сразу нажать
  «Сохранить» (blur отрабатывает до click, состояние чипов успевает
  обновиться).
- Подсказки: `role="combobox"` на input (`aria-expanded`, `aria-controls`,
  `aria-autocomplete="list"`, `aria-activedescendant`), список — `role="listbox"`,
  пункты — `role="option"`. Открывается по фокусу/вводу, закрывается по Esc
  и клику вне. Фильтр локальный по подстроке, выбранные теги исключены,
  максимум 8 пунктов, у каждого частота (`12 пакетов`). Первый пункт
  подсвечен; ArrowUp/ArrowDown двигают подсветку, Enter выбирает.
- Пункт «Создать „foo“» показывается, когда draft валиден, не пуст и его нет
  среди подсказок.
- Состояния: «Загружаем теги…» на время первой загрузки; при ошибке список
  просто пуст — поле работает как свободный ввод, ошибка не показывается
  (подсказки — не критичный путь).
- Поле не рендерит собственных диалогов: список — `Popover` из
  `@/components/animate-ui/components/radix/popover` внутри `Dialog`
  (стандартная вложенность Radix; см. риск §8).

### 6.3. Загрузка подсказок

`frontend/src/components/packages/use-workshop-tags.ts`:
`useWorkshopTags()` → `{ tags, loading }`. Один запрос
`listWorkshopTags({ limit: 200 })` при монтировании. Модульный кеш с TTL 60 с
и дедупликацией in-flight запросов: повторное открытие диалога не спамит API.
Ошибка кешируется на TTL как пустой список.

Сервис в `frontend/src/api/services/scripting-packages.ts`:
`listWorkshopTags(params)` → `scripting-packages/workshop/tags`.

### 6.4. Интеграция в диалог

`package-edit-dialog.tsx`: состояние `tags` меняется с `string` на `string[]`
(из `entry.tags`, затем из `getScriptingPackage`), рендерится `<TagInput>`
вместо `<Input>`, в `updatePackageMetadata` уходит `tags` как есть. `parseTags`
из `workshop-dialogs.tsx` удаляется — после изменения он больше нигде не
используется.

Поле блокируется, пока `detailsState !== "ready"` или идёт отправка, как
остальные поля.

## 7. Testing

Сервер (`pnpm --filter server test`):

- `package-workshop.service.spec.ts`: `tags()` передаёт в запрос нормализованные
  `q`/`limit`/`offset`; строки маппятся в `{ tag, count: number }`
  (`count` приходит строкой из Postgres); пустой `q` даёт `%`-паттерн `''`;
  `limit`/`offset` зажимаются.
- Контроллер (если покрыт): `GET workshop/tags` не перехватывается `:id`.

Фронтенд (`pnpm --filter frontend test`):

- Новый `tag-input.test.tsx`: добавление по Enter и запятой; клик по подсказке;
  «Создать „foo“»; невалидный draft не добавляется и показывает подсказку;
  дубль игнорируется; лимит 10; Backspace на пустом вводе; кнопка удаления
  чипа; выбранные теги исключены из подсказок; ошибка загрузки не блокирует
  ввод.
- `PackagesTab.test.tsx`: сценарий редактирования заполняет теги новым полем
  (чипы вместо строки), сохранение уходит с массивом.
- `use-workshop-tags`: один запрос на несколько монтирований в пределах TTL.

## 8. Risks

- **Popover внутри Dialog.** Radix-портал и фокус-трап: если список окажется
  за трапом, `modal={false}` на Popover или `container` внутри контента
  диалога. Проверяется тестом и вручную.
- **jsdom.** Radix Popper требует `ResizeObserver`/`DOMRect`; если тесты
  упадут, список рендерится без портала в тестовой среде через тот же
  компонент (не отдельная реализация).
- **Кеш подсказок** может отставать на 60 с от только что опубликованного
  пакета — приемлемо, тег появляется в подсказках после TTL.
- **Объём каталога.** `GROUP BY` по распакованному jsonb — seq scan. При сотнях
  пакетов это миллисекунды; при росте — GIN-индекс или материализованная
  таблица тегов (вне задачи).
- **Расхождение правил.** Клиентская валидация дублирует regex сервера; тест
  фиксирует оба поведения, сервер остаётся источником правды (`invalid_tags`
  по-прежнему возвращается и показывается в форме).

## 9. Decisions log

- Пользователь: подсказки только из тегов опубликованных пакетов workshop.
- Пользователь: поиск по тегам пока не делаем — только подсказки при
  редактировании.
- Пользователь: берём свой компонент, без новых зависимостей (вариант C).
- Принято мной: эндпоинт `workshop/tags` с частотами, а не отдельная таблица
  тегов — формат хранения уже достаточен.
- Принято мной: `parseTags` удаляется, состояние тегов в диалоге — `string[]`.
- Принято мной: подсказки грузятся одним запросом с кешем 60 с, фильтрация
  локальная (каталог небольшой, лишние запросы на каждый символ не нужны).
