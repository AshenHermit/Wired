# Запекание импортируемых ассетов при сборке runtime-артефакта

Статус: принято, реализуется по docs/superpowers/plans/2026-11-12-package-asset-bake.md.

## Задача

Пакет, опубликованный пользователем, может содержать сырые ассеты, которые Godot умеет
только импортировать: `.glb`, `.gltf`. В редакторе они работают, потому что редактор их
импортирует. Рантайм комнаты — экспортированная сборка, у неё нет загрузчика glTF: любая
сцена, которая ссылается на `res://.../dude.glb`, после переписывания путей превращается
в `user://wired/rooms/<room>/packages/<slug>/<revision>-<artifactKey>/player/dude.glb`,
и загрузка падает с `No loader found for resource`.

Сейчас каждый автор вынужден придумывать обходной путь: вручную запекать модель в
отдельную сцену, держать её в пакете и не забывать переуказывать ссылки. Это должно
работать само.

## Что уже есть

- `PackageDeliveryService.buildArtifact` вызывает `PackageClosureResolver.resolve`,
  получает `ResolvedClosure` (`rootFiles`, `bytes`, `rootTextFiles`,
  `dependencyTextFiles`) и пишет артефакт в
  `<packagesFilesDir>/<packageId>/runtime/v2/<roomId>/<revision>/<artifactKey>/`.
- `writeArtifact` пишет каждый файл, для текстовых (`.tscn`, `.tres`, `.gd`) применяет
  `rewritePackageReferences` (`res://packages/<slug>/...` → `user://...`), считает
  size+sha256 для манифеста. `.import` пропускается.
- `artifactKey` = sha256 от списка `(packageId, revision)` замыкания; готовый артефакт
  переиспользуется с диска.
- Сайдкары `.import` теперь публикуются как нормализованные пресеты (см.
  `2026-11-12-package-import-presets-design.md`): в них лежат `settings/loop_mode` по
  именам анимаций и `_subresources/materials/<surface>/use_external/{enabled,path}`.
- На сервере есть бинарник Godot 4.8-beta2 (`config.godotRuntime.executablePath`), тот же,
  что запускает комнаты; запуск процессов уже реализован в
  `GodotRuntimeProcessFactory`.

## Проверено пробой

Тот же бинарник в режиме `--headless --path <project> --script res://tool.gd` умеет
`GLTFDocument.append_from_file` → `generate_scene` → `PackedScene.pack` →
`ResourceSaver.save`: на `cura_player/player/dude.glb` (5.07 МБ, 16 узлов) запекание
занимает **128 мс** и даёт самодостаточный `.scn` (12.5 МБ), внутри которого **нет** ссылки
на исходный `.glb` — меши, текстуры, скелет и анимации лежат внутри файла. Ни
`.godot/imported`, ни `.import` для этого не нужны.

## Решение (вариант 1: запекание при сборке артефакта)

При сборке runtime-артефакта сервер находит в артефакте сырые glTF-ассеты, запекает каждый
в соседний `<asset>.scn`, добавляет его в манифест и переписывает ссылки во всех текстовых
файлах артефакта на запечённый файл. Автор ничего не делает: публикация с `.glb` работает
и в редакторе, и в игре.

Пресет импорта применяется на этапе запекания: запечённая сцена получает те же
`loop_mode` и внешние материалы, что автор видит в редакторе.

### 1. Где и как

- Точка входа — `PackageDeliveryService.writeArtifact` (после разрешения замыкания,
  до записи файлов в staging): собирает задания на запекание из `resolved.rootFiles`.
- Задание: `{ source: "<rel>.glb", output: "<rel>.glb.scn", settings: {...}, preset: "<normalized .import>" }`.
- В замыкании ассеты есть только у корневого пакета (`bytes` материализуются лишь для него),
  поэтому запекание затрагивает только файлы корневого пакета. Ссылки на них из пакетов-зависимостей
  переписываются, если такие ссылки есть в их текстовых файлах.
- Новый сервис `AssetBakeService` (`packages/server/src/scripting-packages/delivery/asset-bake.service.ts`):
  - `planJobs(resolved, slug): BakeJob[]` — выбирает ассеты и собирает настройки;
  - `bake(jobs: BakeJob[]): Promise<Map<string, Buffer>>` — кэш → процесс → результат.
- Инструмент запекания — обычный ассет сервера `packages/server/godot_bake/`:
  `project.godot` (минимальный) и `wired_bake.gd`. Путь настраивается
  `GODOT_BAKE_PROJECT_PATH` (по умолчанию `./godot_bake`, резолв от cwd, как остальные пути).

### 2. Как запускается процесс

На один артефакт — один процесс Godot, сколько бы ассетов в нём ни было.

1. Временный каталог `os.tmpdir()/wired-bake-<random>/`:
   `project.godot`, `wired_bake.gd`, `jobs.json` и дерево `packages/<slug>/...` — копия
   файлов ревизии (не переписанных: пресет и материалы должны резолвиться как в редакторе).
   Отдельного лимита на копию нет: объём уже ограничен `MAX_PACKAGE_TOTAL_SIZE` (256 МБ)
   на публикации.
2. Запуск `executablePath --headless --path <tmp> --script res://wired_bake.gd -- res://jobs.json`
   через фабрику процессов: без наследования stdio, таймаут `GODOT_BAKE_TIMEOUT_MS`
   (по умолчанию 30 000, чтобы уложиться в 30-секундный таймаут HTTPRequest у рантайма),
   при таймауте — kill дерева процессов. Одновременных процессов не больше
   `GODOT_BAKE_MAX_CONCURRENCY` (по умолчанию 1); лишние сборки ждут.
3. Скрипт для каждого задания: `append_from_file` → `generate_scene` → применить пресет →
   `PackedScene.pack` → сохранить в `res://packages/<slug>/<output>`; в конце печатает
   одну строку `WIRED_BAKE_OK <json>` со сведениями по каждому заданию (путь, байты,
   применённые анимации и материалы, предупреждения) или `WIRED_BAKE_ERROR <json>`
   и выходит с кодом 1.
4. Сервер читает `output`-файлы, складывает байты в кэш и возвращает их вызывающему.

### 3. Применение пресета внутри скрипта

Пресет приходит как нормализованный `.import` (тот же текст, что публикуется). Скрипт
разбирает только два блока:

- `_subresources/animations/<name>/settings/loop_mode` — после `generate_scene` найти
  `AnimationPlayer`, для каждой анимации с таким именем выставить `Animation.loop_mode`.
  Неизвестное имя → предупреждение, не ошибка.
- `_subresources/materials/<key>/use_external/{enabled,path}` — для каждого
  `MeshInstance3D` и каждой поверхности взять `material.resource_name`; если ключ совпал
  и `enabled == true`, назначить `load(path)` (путь внутри временного проекта уже
  `res://packages/<slug>/...`, поэтому `.tres` резолвится как в редакторе). Ключ без
  совпадения → предупреждение с именем материала.
- `path` из пресета может указывать на файл, которого нет в артефакте (например, материал
  удалён): это ошибка задания `material_missing`, а не тихий откат на встроенный материал.
- **Внешние ресурсы не должны попасть в `.scn`.** Всё, что скрипт загружает с диска
  (материалы пресета, их текстуры), перед упаковкой дублируется и получает пустой
  `resource_path` рекурсивно по подресурсам, поэтому `ResourceSaver` пишет данные внутрь
  файла. Иначе в `.scn` остались бы `res://packages/...`-пути, а `.scn` — бинарный и не
  участвует в переписывании путей на сервере, то есть повторил бы ошибку исходного `.glb`.
  Побочный эффект: запечённая сцена самодостаточна и не зависит от `.tres`/текстур в
  артефакте; размер растёт (см. «Риски»).

### 4. Переписывание ссылок

- Карта `assetRelPath → outputRelPath` (например `player/dude.glb → player/dude.glb.scn`)
  передаётся в `writeArtifact` и применяется в том же проходе, что и `rewritePackageReferences`,
  **после** него: сначала `res://packages/<slug>/...` превращается в
  `user://wired/rooms/.../packages/<slug>/...`, затем точное вхождение пути ассета
  заменяется на путь запечённого файла.
- Это покрывает и `[ext_resource path=...]`, и `preload("...")`/`load("...")` в `.gd`.
- Сырой `.glb` остаётся в артефакте (не ломает `FileAccess`-сценарии и откат), его ссылки
  просто больше не используются сценами. Удаление сырого файла — отдельная задача.

### 5. Манифест артефакта

- Каждый запечённый `.scn` добавляется в `files` с `size` и `sha256` (как обычный файл),
  поэтому клиент скачивает и проверяет его тем же кодом, что и остальные файлы; отдельного
  формата доставки нет.
- `sceneDependencies` не меняется.
- `.import` по-прежнему не попадает в артефакт.

### 6. Кэш

- Каталог `<packagesFilesDir>/bake-cache/`, файл
  `<sha256(исходник)>-<sha256(пресет + BAKE_TOOL_VERSION)>.scn`, где `BAKE_TOOL_VERSION` —
  константа рядом с инструментом, её меняют при изменении логики запекания.
- Ключ не содержит комнату/ревизию: результат запекания самодостаточен (все ресурсы
  внутри), поэтому один и тот же ассет переиспользуется во всех комнатах.
- Попадание в кэш — байты читаются с диска, процесс Godot не запускается.
- Запечённый файл больше `MAX_FILE_SIZE` рантайма (64 МиБ) → сборка падает с
  `package_asset_bake_failed` и причиной `baked_file_too_large` (иначе манифест отвергнет
  весь пакет уже в комнате).
- Ограничение объёма `GODOT_BAKE_CACHE_MAX_BYTES` (по умолчанию 512 МБ), вытеснение по
  времени изменения (самые старые первыми) после успешной записи.
- Кэш не является источником истины: его потеря означает лишь повторное запекание.

### 7. Инвалидация готовых артефактов

`artifactKey` сейчас зависит только от `(packageId, revision)`, поэтому уже собранные
артефакты не заметят новую логику. В `computeArtifactKeys` добавляется константа
`ASSET_BAKE_VERSION` (в хеш вместе со списком ревизий). Изменение версии → новые ключи →
новые каталоги артефактов; старые удаляются штатным `pruneArtifacts`.

### 8. Политика ошибок

- Запекание не удалось (битый glb, таймаут, отсутствующий материал, нет бинарника):
  сборка артефакта падает с `package_asset_bake_failed` и текстом, в котором есть
  пакет, файл и причина. Сцена без запекания в рантайме всё равно не работает, поэтому
  тихий откат означал бы ту же ошибку, но без диагностики.
- Ошибка одного ассета не мешает запечь остальные в том же процессе: скрипт собирает все
  ошибки и печатает их одним ответом, чтобы автор увидел их списком.
- Предупреждения (неизвестная анимация, несовпавший ключ материала) не валят сборку, но
  логируются сервером с префиксом пакета.

## Не-цели

- `.gltf` с внешними `.bin`/текстурами и FBX/DAE/OBJ: в v1 поддерживается только
  самодостаточный `.glb`. Остальные форматы дают `package_asset_bake_failed` с причиной
  `unsupported_asset_format` и списком файлов; предупреждение пишется в лог при сборке
  артефакта (публикация не меняется).
- Ассеты пакетов-зависимостей: запекаются только файлы корневого пакета (в замыкании для
  зависимостей материализуются лишь текстовые файлы). Ссылка на чужой `.glb` даёт
  `package_asset_bake_failed` с причиной `dependency_asset_unsupported`.
- Запекание текстур/звука: ими уже занимается `AssetDeriver` на рантайме.
- Изменения в редакторе и в аддоне: автор по-прежнему видит `.glb` в дереве.
- Кэш между пакетами по подобию ассетов: ключ только по содержимому файла и пресету.
- Удаление сырых ассетов из артефакта.
- Запекание во время публикации или лениво при первом старте комнаты (варианты 2 и 3
  отклонены).

## Тесты

- Jest, `asset-bake.service.spec.ts` (раннер процессов подменяется): выбор ассетов,
  сборка `jobs.json`, попадание/промах кэша, таймаут, `WIRED_BAKE_ERROR`, отсутствующий
  материал, лимит входных данных.
- Jest, `package-delivery.service.spec.ts`: артефакт содержит `.scn`; `files` содержит
  запись с size+sha; `[ext_resource]` в `.tscn` переписан на `.scn`; `.import` в артефакте
  отсутствует; ключ артефакта изменился при смене `ASSET_BAKE_VERSION`.
- GDScript, `tests/asset_bake_smoke.gd`: на синтетическом `.glb` (генерируется скриптом
  через `GLTFDocument` из простой сцены) проверяет, что пресет применяется (loop_mode и
  внешний материал), в результате нет ссылок на исходник и файл загружается как
  `PackedScene`.
- Опциональная интеграция `WIRED_GODOT_INTEGRATION=1`: запекание реального
  `examples/cura_player/player/dude.glb` с его `.import` — 9 анимаций с `loop_mode = 1`,
  14 внешних материалов, загрузка результата без ошибок.

## Риски

- Размер: `.scn` для модели на 5 МБ занимает 12.5 МБ. Кэш и артефакты вырастут; лимит
  кэша и штатное вытеснение артефактов это ограничивают, но трафик комнаты вырастет.
- Время: 128 мс на модель + копирование пакета во временный проект. На пакете с десятком
  моделей — единицы секунд на сборку артефакта, один раз на ключ артефакта.
- `resource_name` материалов зависит от импортёра; если он не совпадёт с ключом пресета,
  материал не применится. Это видно в предупреждениях и проверяется смоук-тестом на
  реальном пакете.
- `.gltf` с внешними `.bin`/текстурами: копирование дерева пакета сохраняет их
  относительные пути, поэтому работает, но тестом не покрыто до первого реального случая.
- Версия Godot фиксирована (4.8-beta2). Смена версии меняет формат `.scn`; запечённые
  файлы попадают в артефакт, а не в репозиторий, поэтому пересобираются автоматически.

## Открытые вопросы (решает исполнитель)

- Точный формат `jobs.json` и структура ответа `WIRED_BAKE_OK` — интерфейс между сервисом
  и скриптом, значения фиксирует план.
- Как именно искать `AnimationPlayer` в сгенерированной сцене (обход дерева против
  `find_children`), если анимаций несколько.
- Нужен ли отдельный признак «ассет уже запечён» в манифесте, или достаточно имени файла
  `.scn` — по умолчанию достаточно.

## Решения по итогам проверки проекта

1. Внешние ресурсы (материалы пресета и их текстуры) **встраиваются** в `.scn`; сайдкар
   `.import` в него не попадает. Это сохраняет внешний вид, который автор видит в
   редакторе, и не требует переписывать бинарный файл после запекания.
2. Ассеты пакетов-зависимостей не запекаются: в замыкании для зависимостей есть только
   текстовые файлы. Ссылка на чужой `.glb` — явная ошибка сборки, а не тихая поломка.
3. Ограничение размера берётся у рантайма (`MAX_FILE_SIZE` = 64 МиБ на файл), а не
   придумывается заново; общий объём уже ограничен публикацией. `MAX_FILES` не трогаем —
   превышение проявится как отказ манифеста, это зафиксировано в рисках.
4. Запекание идётinline при сборке артефакта, но ограничено по времени (`30 000` мс) и по
   параллелизму (`1`), чтобы не выйти за 30-секундный таймаут манифеста у рантайма.
   Первый запрос может не успеть — повторный придёт уже к собранному артефакту; это
   допустимо, потому что артефакт кэшируется по ключу.
5. `.gltf` с внешними буферами в v1 не поддерживается: кэш ключуется по содержимому
   одного файла, а `.gltf` зависит от соседних `.bin`/текстур. Отказ с понятной причиной.
6. Предупреждение о неподдерживаемом формате печатается при сборке артефакта: отдельного
   шага в публикации не появляется.
