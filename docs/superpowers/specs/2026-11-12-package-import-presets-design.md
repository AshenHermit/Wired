# Пресеты импорта в пакетах (design)

Дата: 2026-11-12. Статус: принято, реализуется по `docs/superpowers/plans/2026-11-12-package-import-presets.md`.

## Задача

При замене модели (`dude.glb` и любой другой) в редакторе сбрасываются настройки импорта: `loop_mode` у анимаций и внешние материалы (`_subresources/materials/*/use_external`). Настройки физически живут только в `*.import`, а ядро считает `*.import` редакторными метаданными: они не попадают в ревизию, не раздаются другим клиентам и не версионируются. Нужен фикс на уровне платформы для всех пользовательских пакетов, а не для `cura_player`.

## Как работает сегодня (проверено по коду)

- `WiredPackageFs.is_editor_metadata()` в `packages/server/godot_project/_wired/addons/wired_bridge/package_fs.gd` относит к метаданным dot-сегменты, `*.uid` и `*.import`. Поэтому `op_snapshot`/`op_collect` их не видят, в ревизию они не уходят, а `op_replace` копирует старые копии из прежнего дерева в staging (локальный кэш редактора выживает, но только на этой машине).
- `frontend/src/godot/bridge/godot-packages-fs.ts` (`isEditorMetadataPath`) повторяет то же правило; `applyPackageRevision` пишет в staging все файлы манифеста через `engine.copyToFS`.
- `packages/server/src/scripting-packages/delivery/package-delivery.service.ts` (`writeArtifact`) кладёт в runtime-артефакт **все** файлы ревизии. Нативному рантайму `.import` с `[remap] path="res://.godot/imported/…"` не годится: такого файла там нет (см. `docs/superpowers/specs/2026-10-30-godot-package-runtime-delivery.md`).
- `packages/server/src/scripting-packages/publish/package-runtime-references.ts`: `TEXT_FILE_EXTENSIONS = ['.tscn', '.tres', '.gd']`, `.import` не участвует в резолве ссылок и slug-переписывании.
- Дефолтный импорт пишет `_subresources={}` — ключ **присутствует, но пуст** (подтверждено `git show a7fb94a^:…/dude.glb.import`). Значит «настроек нет» надо определять как пустой словарь, а не как отсутствие ключа.

## Почему пресет без `[remap] path` и `[deps]` безопасен

Проверено по исходникам движка:

- `core/io/resource_importer.cpp`, `ResourceFormatImporter::_get_path_and_type`: `path`/`[deps]` — результат импорта, а не настройки. Если `path` пуст, а импортёр пишет файлы (scene/texture пишут), возвращается `ERR_FILE_CORRUPT` — файл означает «ещё не импортирован».
- `editor/file_system/editor_file_system.cpp`, `_reimport_file` (L2802-2904): `[params]` (включая `_subresources`) читаются из файла, импортёр берётся из `[remap] importer`, отсутствующие параметры добиваются дефолтами импортёра; после импорта файл перезаписывается целиком уже с `path` и `[deps]`.
- `_test_for_reimport` (L573-740): нет `uid` → принудительный реимпорт; нет `dest_files` → реимпорт; `valid=false` → наоборот, не реимпортит.
- `Aureliolo/gdharness#1361` описывает это состояние как штатное: «The new sidecar has no `path=` under `[remap]` and no `[deps]`, as a sidecar does before the engine has imported from it».

Обязательное условие: в `[remap]` остаются `importer`, `importer_version`, `type`, `uid`. Если убрать секцию целиком, редактор ищет импортёр по расширению с `load_default = true` (поверх лягут `importer_defaults/*` из `project.godot`), а `uid` сгенерируется заново — сломается ссылка на модель в `player_model.tscn`.

## Решение

Оба слоя — в ядре (`_wired`). Backend байты не мутирует: `createDraft` объявляет манифест с size+sha256, а `publish` сверяет с ним байты, поэтому подмена на сервере ломала бы проверку.

- **A. Пресет импорта как содержимое пакета.** `*.import` перестаёт быть метаданными и публикуется в нормализованном виде: без `path`, `path.*`, `metadata`, `valid` и без секции `[deps]`. Остаются `importer`, `importer_version`, `type`, `uid`, `[params]` (включая `_subresources`). Ревизия переносима между машинами и не содержит путей в `.godot/imported`.
- **B. Кэш пресетов и восстановление в редакторе.** Нормализованный пресет дублируется в `<package>/.wired/import-presets/<rel_path>.import` (dot-каталог = редакторные метаданные: не публикуется, переживает swap). Если исходник заменили и Godot перегенерировал `.import` с пустым `_subresources`, хук в addon возвращает пресет в живой `.import` и переимпортирует файл — настройки видны в редакторе сразу, а `snapshot` и `collect` видят уже исправленный файл.

Восстановление делает **addon**, а не `collect`: иначе опубликованный пресет расходился бы с тем, что показывает редактор, и `snapshot` никогда не совпал бы с манифестом.

## Дизайн по слоям

### 1. Ядро: `_wired/addons/wired_bridge/package_fs.gd`

1. `is_editor_metadata()`: убрать правило для `*.import`; `*.uid` и dot-сегменты остаются. Обновить doc-комментарий класса.
2. `normalize_import_text(text: String) -> String` — построчная, идемпотентная:
   - вырезать секцию `[deps]` целиком (до следующей секции);
   - в `[remap]` вырезать ключи `path`, `path.*`, `metadata`, `valid`;
   - вырезать строки-комментарии (`;`), чтобы служебный заголовок кэша не попадал в публикацию.
3. `op_snapshot`: для `*.import` хэшировать **нормализованный** текст, иначе после публикации snapshot навсегда покажет расхождение. Отбрасывать «осиротевшие» `*.import`, у которых нет исходника в пакете (см. п. 8).
4. `op_collect`: для `*.import` отдавать нормализованный текст (size/sha по нему). Никакой подстановки из кэша — к моменту collect файл уже исправлен хуком.
5. `op_replace`:
   - `_copy_editor_metadata` больше не перетирает `.import`, пришедшие в staging;
   - фолбэк для обратной совместимости: если в staging есть исходник, а его `.import` нет — скопировать старый локальный `*.import`;
   - после успешного swap обновить кэш по staged `*.import`: непустой `_subresources` → записать пресет, пустой → **удалить** запись (ревизия авторитетна: осознанный сброс, опубликованный другим клиентом, не должен воскресать), исходника нет → удалить запись.
6. Формат кэша `.wired/import-presets/<rel_path>.import`: первая строка `; applied-sha256=<sha256 исходника>`, далее нормализованный пресет.
7. `restore_import_presets(package_slug: String) -> Array[String]` — новая функция, вызывается хуком addon:
   - для каждого живого `*.import` с пустым `_subresources`, у которого есть исходник и кэшевый пресет с непустым `_subresources`, и `applied-sha256` не совпадает с текущим sha исходника — записать пресет в живой `.import`;
   - после записи обновить `applied-sha256` на текущий sha;
   - вернуть пути восстановленных `.import`, чтобы addon вызвал `reimport_files`.
   Ограничение «один раз на версию исходника» закрывает сценарий «заменил модель → увидел сброс → сам сбросил ещё раз»: после восстановления `applied-sha256` уже равен текущему sha, повторной подстановки не будет.
8. Осиротевшие `*.import` (исходника нет): не попадают в `snapshot`/`collect` и не кэшируются. Удаление через `op_delete_files` удаляет `.import` вместе с выбранным исходником (это содержимое); кэш остаётся и восстановит пресет, когда исходник появится снова.
9. `op_rename`: кэш переезжает вместе с каталогом; `import` уже есть в `SLUG_REWRITE_EXTENSIONS`, поэтому ссылки в кэше переписываются тем же проходом.

### 2. Хук в addon: `_wired/addons/wired_bridge/plugin.gd`

- Подключиться к `EditorInterface.get_resource_filesystem().filesystem_changed` с дебаунсом (`call_deferred` + флаг, не чаще одного прогона на пачку изменений).
- Пройти по живым каталогам `res://packages/<slug>/`, вызвать `WiredPackageFs.restore_import_presets(slug)`.
- Если что-то восстановлено — `reimport_files(восстановленные_исходники)`. Повторный `filesystem_changed` от реимпорта ничего не найдёт: `_subresources` уже непустой.
- Защита от рекурсии: флаг «идёт восстановление», во время которого хук не реагирует.

### 3. Frontend: `frontend/src/godot/bridge/godot-packages-fs.ts`

`isEditorMetadataPath()` — убрать `.import`. Функция экспортируется, но больше нигде не используется; правило должно совпадать с ядром.

### 4. Backend

- `delivery/package-delivery.service.ts`, `writeArtifact`: пропускать файлы с расширением `.import` (не писать в артефакт и не включать в `files`/манифест).
- `publish/package-runtime-references.ts`: **не** добавлять `.import` в `TEXT_FILE_EXTENSIONS`. Иначе один устаревший `use_external/path` (удалённый `.tres`, пакет, скопированный из другого проекта, комната, из которой убрали зависимость) начнёт валить публикацию ошибками `package_dependency_*`, а артефакт будет декодировать файл, который потом выбрасывает. Зависимости из `.import` не строятся; материалы, на которые он ссылается, обычно уже достижимы через `.tscn`/`.tres`.
- Миграции нет: пакеты, в ревизии которых `.import` нет, работают как раньше.

### 5. `cura_player`

После выкатки достаточно опубликовать пакет заново: в локальном FS редактора `.import` уже с настройками, и он уйдёт в ревизию как пресет. Ручной ритуал «не удалять glb, чтобы сохранить `.import`» становится необязательным.

## Тесты

GDScript smoke (`_wired/tests/package_fs_smoke.gd`):

- переписать `_test_metadata_excluded`, `_test_metadata_preserved`, `_test_delete_files_selected_directory`, `_test_delete_files_keeps_metadata_of_selected_file`;
- нормализация: `path`/`[deps]` срезаны, `[params]`/`_subresources` сохранены, комментарии удалены;
- `snapshot` и `collect` дают одинаковый sha для одного и того же `.import`;
- `op_replace` с пресетом в ревизии → в FS лежит нормализованный текст, `path`/`[deps]` отсутствуют;
- `op_replace` без `.import` в ревизии → старый локальный `.import` сохранён;
- `op_replace` с пустым `_subresources` → кэшевая запись удалена;
- `restore_import_presets`: пустой `_subresources` + сменившийся sha исходника → пресет записан, `applied-sha256` обновлён; повторный вызов ничего не меняет; при неизменном sha (осознанный сброс) не срабатывает;
- осиротевший `.import` не попадает ни в `snapshot`, ни в `collect`, ни в кэш.

Jest: `writeArtifact` не пишет `*.import` и не включает его в манифест артефакта; `isTextPackageFile('.import') === false`.

Vitest: `isEditorMetadataPath('a.glb.import') === false`.

## Риски и краевые случаи

- Godot после импорта снова дописывает `path`/`[deps]`; нормализация при каждом `collect`/`snapshot` обязательна, иначе ревизии «дрожат».
- Кэш может воскресить loop mode для анимаций, которых в новой модели нет; лишние ключи безвредны.
- Кэш — редакторные метаданные: не публикуется, занимает место в FS порядка размера `.import`.
- Хук на `filesystem_changed` сканирует `.import` всех пакетов; на пакете с сотнями текстур это надо ограничить (проверять только файлы, у которых изменился исходник или сам `.import`, плюс дебаунс).
- `uid` в пресете сохраняется, поэтому ссылки по `uid://` в сценах не рвутся при переимпорте.

## Не-цели

- Не меняем формат импортных настроек и не выносим их в отдельный файл-рецепт.
- Не раздаём `.import` нативному рантайму.
- Не строим граф зависимостей по `.import`.
- Не добавляем UI для просмотра/редактирования пресетов; `.import` показывается как обычный файл пакета.
- Никакого предупреждающего тоста при подстановке из кэша — восстановление молчаливое.

## Решения, принятые по итогам ревью дизайна

1. «Настроек нет» = `_subresources={}`, а не отсутствие ключа (подтверждено старым `.import`).
2. Подстановка живёт в addon-хуке с записью обратно в файл, а не в `collect`; `snapshot`/`collect` всегда хэшируют один и тот же живой текст.
3. Кэш инвалидируется ревизией (`op_replace`) и ограничен `applied-sha256`, поэтому осознанный сброс не откатывается.
4. Осиротевшие `.import` отбрасываются.
5. `.import` не участвует в графе зависимостей и не может завалить публикацию.
6. В UI `.import` — обычный файл пакета.
