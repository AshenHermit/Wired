# Brotli для файлов редактора — дизайн

## Зачем

`GET /godot-editor/*` раздаёт официальный WASM-редактор Godot 4.8-beta2 (десятки МБ, основная часть — `godot.editor.wasm`) безо всякого сжатия: ни nginx, ни Nest не жмут. Браузер перекачивает всё дерево при каждом открытии комнаты (для файлов редактора не выставляются ни ETag, ни Cache-Control). Brotli на wasm/js даёт кратное сжатие; предсжатие на build-time делает это бесплатным по CPU.

## Цели / не-цели / анти-цели

- **Цель:** ответы на `/godot-editor/*` сжимаются brotli для клиентов, которые его просят (`Accept-Encoding: br`), без CPU-затрат на каждый запрос; файлы редактора revalid'ятся по ETag (304 вместо перекачки).
- **Не-цель:** сжатие файлов godot-проекта (`godot-project/*`), web-экспорта, файлов пакетов (авторских и runtime) и JSON API. Расширение на них позже — переворот флага в `serveStaticAsset`, но сейчас не делаем.
- **Анти-цель:** on-the-fly сжатие на горячем пути; любое сжатие ответов, которые читает Godot (нативный рантайм/web-клиент ломается от `Content-Encoding`, см. комментарий в `package-delivery.controller.ts`).

## Подходы

- **A. On-the-fly middleware (`compression` + brotli) на `/godot-editor/*`** — минимум кода, но пересжатие ~40 МБ на каждую загрузку редактора каждым пользователем; качество ниже максимального. Отклонено: постоянный CPU ради результата, который можно получить один раз.
- **B. Предсжатые sidecars (выбран)** — `pnpm fetch:editor` пишет рядом `*.br` (build-time, качество максимум), сервер только выбирает между raw и `.br` по `Accept-Encoding`. Дерево редактора — gitignored-артефакт, закреплён пином версии, меняется только со сменой пина — идеальный кандидат на предсжатие. Sidecars автоматически попадают в Docker-образ (образ запускает `fetch:editor` при сборке).

## Решения

1. **Генерация sidecars** — новая библиотека `packages/server/scripts/lib/editor-brotli.mjs` (Node built-in `zlib.brotliCompressSync`, качество 11). `fetch-godot-editor.mjs` вызывает её после установки; шаг выполняется и когда установка уже есть (backfill до раннего выхода). Правила: файлы меньше ~1 КБ и случаи «`.br` вышел не меньше raw» не получают sidecar.
2. **Раздача** — `serveStaticAsset` получает опцию `precompressed?: boolean`, включается только в `getEditorFile`. При включённой опции всегда ставится `Vary: Accept-Encoding`; разбор `Accept-Encoding` с q-значениями (`q=0` — не принять; wildcard `*` не поддерживаем — браузеры шлют `br` явно). Если `br` принят и рядом с файлом есть актуальный `<file>.br` — отдаётся он с `Content-Encoding: br`, `Content-Type` от исходного пути (не от `.br`, иначе `application/wasm` превратится в octet-stream и сломается `instantiateStreaming`) и `Content-Length` sidecar-а. Иначе — как сейчас.
3. **Актуальность sidecar** — существование + `mtime(.br) >= mtime(raw)`; установки редактора заменяют файлы целиком, этого достаточно.
4. **Boot-backfill на сервере** (моя инициатива, можно выбросить): при старте backend фоново досжимает отсутствующие/устаревшие sidecars, чтобы старые dev-установки, не перезапускавшие `fetch:editor`, тоже получали brotli. До окончания — отдаётся raw; ошибка записи (read-only каталог) — warn и raw навсегда.
5. **Revalidate для редактора** — `getEditorFile` включает `revalidate: true` (ETag + 304). ETag считается от реально отдаваемого файла (raw или sidecar); повторное открытие комнаты перестаёт перекачивать дерево.

## Ограничения

- Трогаем только маршрут `godot-editor/*` (читается браузером — декодирует brotli сам) и файлы внутри gitignored `godot_editor/`; `godot_project/_wired/` (коммитнутый ресурс) не затрагиваем.
- Новых зависимостей и env-переменных нет.
- Прокси не мешают: nginx/Next-rewrites пропускают `Content-Encoding` насквозь.
