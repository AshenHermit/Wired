# Дизайн: переход Wired на официальный Godot 4.8-beta2

Статус: реализовано и проверено на 4.8-beta2.

## Зачем

Web-редактор Godot 4.7.2 не умеет удалять файлы из FileSystem dock:
`OS_Web::move_to_trash` в нём не реализован. В 4.8-beta2 и master этого
исправления уже есть: каталог удаляется рекурсивно, файл — через
`DirAccess::remove_absolute`. Плюс в 4.8 исправлены другие места web-редактора.

Мы не хотим собирать форк и поддерживать CI. Берём официальные сборки
**4.8-beta2** и переводим на них Wired целиком: web-редактор, нативный runtime
для сервера и шаблоны web-экспорта.

## Что берём

Источник: GitHub release `godotengine/godot-builds`, тег `4.8-beta2`.

| Артефакт | Размер | Назначение |
|---|---:|---|
| `Godot_v4.8-beta2_web_editor.zip` | 32 990 172 | web-редактор |
| `Godot_v4.8-beta2_win64.exe.zip` | 64 448 151 | runtime win32-x64 |
| `Godot_v4.8-beta2_win32.exe.zip` | 66 988 384 | runtime win32-ia32 |
| `Godot_v4.8-beta2_windows_arm64.exe.zip` | 64 850 220 | runtime win32-arm64 |
| `Godot_v4.8-beta2_linux.x86_64.zip` | 62 274 839 | runtime linux-x64 |
| `Godot_v4.8-beta2_linux.arm64.zip` | 58 878 748 | runtime linux-arm64 |
| `Godot_v4.8-beta2_linux.x86_32.zip` | 58 241 294 | runtime linux-x86_32 |
| `Godot_v4.8-beta2_linux.arm32.zip` | 55 085 572 | runtime linux-arm32 |
| `Godot_v4.8-beta2_macos.arm64.zip` | 61 048 120 | runtime darwin-arm64 |
| `Godot_v4.8-beta2_macos.x86_64.zip` | 67 913 304 | runtime darwin-x64 |
| `Godot_v4.8-beta2_export_templates.tpz` | 1 349 622 957 | шаблоны web-экспорта |

Контрольные суммы берём из официального `SHA512-SUMS.txt`: это sha512, а не
sha256. Поэтому проверку runtime и шаблонов переводим на sha512 — так же, как
уже сделано для web-редактора. Это избавляет от скачивания 1.35 ГБ только ради
вычисления sha256.

Версия в пинах — `4.8-beta2`. Каталог шаблонов Godot — `4.8.beta2`
(`GODOT_VERSION_FULL_CONFIG` = major.minor.patch.status.module, без `-`).
Web-редактор своего `VERSION` в архиве не содержит; `fetch:editor` пишет его сам.

## Что меняем

### 1. Web-редактор

`packages/server/scripts/fetch-godot-editor.mjs`:
- `VERSION = '4.8-beta2'`;
- ZIP name/size/sha512 — из таблицы;
- URL переводим на `https://github.com/godotengine/godot-builds/releases/download/4.8-beta2/...`
  (сейчас скрипт смотрит в релизы `godotengine/godot`, где лежит 4.7.2).

`CORE_FILES` не меняются: в архиве 4.8-beta2 есть `godot.editor.js`,
`godot.editor.wasm`, `godot.editor.html`, плюс новый
`godot.editor.iframe.html`, который установщик скопирует автоматически.

### 2. Нативный runtime

`packages/server/scripts/lib/runtime-install.mjs`:
- `RUNTIME_VERSION = '4.8-beta2'`;
- обновить все `ASSETS`: имена, размеры, sha512, `sourceExecutable`;
- macOS больше не universal: `darwin-x64` и `darwin-arm64` — отдельные ключи
  и отдельные ассеты;
- `PLATFORM_KEYS.darwin` мапит `x64`/`arm64` на разные ключи;
- `verifyRuntimeArchive` считает sha512 и сверяет `asset.sha512`;
- сообщения и `fetch-godot-runtime.mjs` говорят `sha512`.

`win32`/`linux` имена исполняемых файлов не меняются: win → `Godot.exe`,
linux → `godot`, macOS → `Godot.app/Contents/MacOS/Godot`.

### 3. Шаблоны экспорта

`packages/server/scripts/lib/export-templates.mjs`:
- `TEMPLATES_VERSION = '4.8-beta2'`;
- `TEMPLATES_DIRECTORY = '4.8.beta2'`;
- `TEMPLATES_ASSET` — новый tpz, размер и sha512;
- `verifyTemplatesArchive` переводим на sha512;
- `fetch-godot-templates.mjs` и его комментарий — sha512.

### 4. Проект и документация

- `packages/server/godot_project/_wired/project.godot`: только
  `config/features` `"4.7"` → `"4.8"`. Файл содержит незакоммиченные правки
  пользователя, поэтому меняем ровно этот токен и ничего больше.
- `AGENTS.md`: текущие упоминания 4.7.2 → 4.8-beta2, `"4.7"` → `"4.8"`,
  команды и комментарии fetch-скриптов.
- `backend.Dockerfile`: комментарий про закреплённую версию.
- Исторические документы `docs/superpowers/specs|plans/*2026-10-31*` и
  результаты прошлых этапов не переписываем.

### 5. Тесты

- `runtime-install.test.mjs`: версия, имена ассетов, URL, sha512, macOS split,
  install-директории `4.8-beta2-*`.
- `export-templates.test.mjs`: версия, tpz, размер, sha512, каталог `4.8.beta2`.
- `editor-install.test.mjs`: версия в фикстуре, если она там проверяется.
- `config.spec.ts`: фикстура runtime.json → `4.8-beta2-win32-x64`.

## Проверка

1. `pnpm --filter server test:scripts` — все Node-тесты.
2. `pnpm --filter server test -- config.spec.ts` — конфиг читает новый runtime.
3. `pnpm fetch:editor` — скачивает и ставит 4.8-beta2 web-редактор.
4. `pnpm fetch:runtime` — ставит 4.8-beta2 win32-x64 и пишет `runtime.json`.
5. `pnpm fetch:templates` — скачивает 1.35 ГБ и ставит web-шаблоны в
   `%APPDATA%\Godot\export_templates\4.8.beta2`.
6. `pnpm export:game` — web-экспорт новым редактором и шаблонами.
7. Headless smoke-тесты проекта новым runtime (`package_fs_smoke` и др.).
8. В браузере: комната открывается, web-редактор стартует, FileSystem dock
   удаляет выбранные файлы, пакеты применяются, Game-вкладка запускается.
9. Проверить, что после `--import` нового редактора в `project.godot` не
   появилось других изменений, кроме `"4.8"`. На копии проекта это уже
   проверено: diff только в `config/features`.

## Риски и ограничения

- 4.8-beta2 — pre-release; возможны регрессии в web-редакторе и экспорте.
- Старые шаблоны 4.7.2 несовместимы с 4.8; после переезда нужен именно
  `4.8.beta2`.
- Docker-образ качает только web-редактор; runtime и шаблоны — локальные
  gitignored-каталоги, как и раньше.
- Скачивание шаблонов — 1.35 ГБ; это разовая операция на машине разработчика.
- Незакоммиченные `main.tscn`, `project.godot` и `.uid` пользователя не
  трогаем, кроме одного токена `"4.8"` в `project.godot`.

## Альтернативы

1. **Официальный 4.8-beta2** — выбран. Минимум поддержки, фикс удаления уже
   внутри, все три платформы и шаблоны есть.
2. **Форк master + GitHub Actions** — даёт точный master, но требует
   поддерживать сборку web editor, Windows/Linux editor и шаблонов, плюс
   хранить артефакты. Оставляем на случай, если beta2 окажется недостаточно.
3. **Остаться на 4.7.2 + bridge-удаление** — уже реализовано, но не лечит
   остальные ограничения web-редактора и требует собственного обходного пути.
