# Этап 6. Интерфейс Packages и сквозные проверки — результаты

Дата: 2026-10-30. Ветка: `working-on-godot-rooms`.
Статус: критерий готовности выполнен.

## Итог

Пакеты попадают в редактор только по явному действию пользователя. Вкладка
Packages показывает все пакеты комнаты и их состояние, позволяет создать
пакет, скачать опубликованную ревизию в `packages/<packageId>/`, убрать
каталог из редактора и опубликовать (Emit) только загруженный пакет.
Автоматической синхронизации пакетов в редактор больше нет; набор загруженных
пакетов живёт в памяти вкладки и после перезагрузки страницы не
восстанавливается.

Game-runtime и Game-клиенты по-прежнему обновляются автоматически после
Emit. Редакторы других пользователей файлы не получают: они видят отметку
«есть новая ревизия» и скачивают её вручную.

## Видимость файлов, записанных напрямую в `rtenv.FS`

Проверено на используемой сборке Godot (редактор в браузере, комната 7):

- После создания пакета и после скачивания ревизии файлы сразу появляются в
  виртуальной ФС и в IndexedDB. Проверка IndexedDB (`/home/web_user/room-7`,
  store `FILE_DATA`) показала
  `/home/web_user/room-7/Wired/packages/11/e2e.txt` сразу после скачивания.
- Уже запущенный Godot-редактор **не замечает** новый каталог `packages/`
  сам по себе: EditorFileSystem кэширует дерево. Ожидание и попытка прокрутки
  дока результат не меняют.
- Поэтому был добавлен узкий editor plugin `addons/wired_bridge` в базовый
  проект `_wired`. Он регистрирует `window.__wiredEditorBridge.rescan()`
  через `JavaScriptBridge.create_callback`; колбэк вызывает
  `EditorFileSystem.scan()`. Фронтенд вызывает его после создания, скачивания
  и удаления пакета.
- Проверено в запущенном web-редакторе: после «Создать пакет» в консоли
  появилось `WIRED_EDITOR_RESCAN_DONE packages=true dirs=["13"]`, и каталог
  стал виден без `Project → Reload Current Project`.
- Плагин работает только в web-редакторе и не влияет на экспорт игры. Если
  мост недоступен (старый проект/сбой плагина), панель по-прежнему показывает
  fallback: сохранить сцены и выполнить `Project → Reload Current Project`.

## Поведение панели

Состояния пакета:

| Состояние | Условие |
| --- | --- |
| «не загружен» | каталога пакета нет в FS |
| «загружен» | пакет скачан/создан в этой сессии, локальные файлы совпадают с базой |
| «есть новая ревизия» | опубликованная ревизия на сервере новее загруженной |
| «локальные изменения» | файлы в каталоге отличаются от базы; также для каталога, оставшегося от прошлой сессии |

Действия:

- «Скачать в редактор» — получает последний манифест, проверяет размер и
  `sha256` каждого файла, применяет файлы в `packages/<packageId>/`, удаляет
  лишние файлы внутри этого каталога и запоминает базу ревизии. Если в
  каталоге уже есть локальные файлы (в том числе от прошлой сессии), сначала
  требуется явное подтверждение.
- «Убрать из редактора» — удаляет только `packages/<packageId>/`; при
  локальных изменениях требуется подтверждение. Файлы соседних пакетов и
  остальной проект не затрагиваются.
- «Создать пакет» — создаёт `ScriptingPackage` на backend и сразу пустой
  каталог `packages/<packageId>/`. Остальные пакеты комнаты не загружаются.
- «Emit» — доступен только для загруженного пакета: читает файлы его
  каталога, создаёт черновик, загружает каждый файл с проверкой размера и
  хеша, публикует ревизию и обновляет базу. Ошибки загрузки/публикации
  показываются в карточке пакета.
- «Обновить» и фоновый опрос `GET /rooms/:roomId/game/packages` раз в 10
  секунд обновляют только статусы; в FS при этом ничего не пишется.

Для каждой карточки также показываются опубликованная и загруженная ревизии,
состояние применения на сервере/runtime и число готовых Game-клиентов.

## Реализация

Frontend:

- `frontend/src/app/room/[room_code]/(godot)/use-room-packages.ts` — состояние
  панели, загрузка/удаление/Emit, опрос статусов. Базы загруженных пакетов
  хранятся в `useRef` и не пишутся в `localStorage`.
- `frontend/src/app/room/[room_code]/(godot)/PackagesTab.tsx` — третья
  вкладка Editor / Packages / Game.
- `frontend/src/app/room/[room_code]/(godot)/editor-bridge.ts` — вызов
  `window.__wiredEditorBridge.rescan()`, если плагин редактора его
  зарегистрировал.
- `packages/server/godot_project/_wired/addons/wired_bridge/` — editor plugin,
  который через `JavaScriptBridge` отдаёт наружу только `rescan()` и вызывает
  `EditorFileSystem.scan()`.
- `godot-packages-fs.ts` — добавлены `exists()` и `createPackageDir()`.
- `package-sync.ts` — добавлен `changedPackageFiles()` для определения
  локальных изменений по базе.
- Удалены Stage 5 `use-package-sync.ts`, его тест и `PackageSyncStatus.tsx`.

Backend не менялся: используются существующие
`POST /scripting-packages`, `GET /rooms/:roomId/game/packages`,
`GET /scripting-packages/:id/manifest` и API ревизий.

## Ручной checklist для локальной Windows-разработки

Предусловия: `pnpm install`; Postgres из `packages/server/.env`;
`pnpm dev:server`; `pnpm --filter frontend dev -- -p 3001`; вход через Google;
комната типа `godot`; для Game-вкладки выполнен `pnpm export:game`.

1. Открыть комнату, перейти в Packages: видны все пакеты комнаты, ни один не
   загружен.
2. Создать пакет: карточка «загружен», в FS есть пустой каталог; другие
   пакеты не появились.
3. Перезагрузить страницу: пакет снова «не загружен»; если каталог остался в
   IndexedDB, он показан как локальные изменения. Нажать «Использовать
   каталог»: файлы становятся baseline, Emit публикует их без удаления.
4. Скачать пакет с опубликованной ревизией: карточка «загружен», ревизии
   совпадают; каталог сразу виден в доке FileSystem. Если мост не сработал,
   выполнить `Project → Reload Current Project`.
5. Изменить файл в редакторе и нажать Emit: публикуется новая ревизия,
   карточка обновляется; в Game-вкладке клиент получает ревизию.
6. Опубликовать ревизию из второй сессии/API и нажать «Обновить»: появляется
   «есть новая ревизия», FS не меняется; скачивание требует подтверждения,
   если есть локальные изменения.
7. Убрать пакет: исчезает только его каталог.
8. Отключить сеть на 10–20 секунд: панель показывает ошибку опроса, после
   восстановления статусы снова обновляются; файлы в редакторе не теряются.
9. Оставить Game-клиент без действий: runtime останавливается по
   `GODOT_ROOM_IDLE_TIMEOUT_MS`; повторное открытие Game начинает новую сессию
   и догоняет опубликованные ревизии.
10. Перезапустить Game и редактор: сохранённая сцена и опубликованные пакеты
    восстанавливаются, editor снова начинает с пустым набором загруженных
    пакетов.

## Решения и ограничения

- Каталоги пакетов не удаляются при старте редактора. Раз набор загруженных
  пакетов сбрасывается, оставшиеся файлы показываются как локальные изменения
  и требуют подтверждения перед заменой/удалением. Это защищает работу
  пользователя ценой того, что редактор не становится буквально пустым.
- Скачивание в никогда не загруженный каталог с файлами тоже требует
  подтверждения.
- Сравнение файлов ограничено списком изменённых путей; построчного diff нет,
  как и предусмотрено планом.
- Владение/блокировка пакетов не входит в этап 6: Emit разрешён backend-правом
  редактирования пакета/комнаты.
- Editor plugin включён в общем базовом проекте `_wired`, поэтому его получают
  все комнаты. Он не влияет на игру и не даёт фронтенду произвольный `eval`:
  наружу выставлен только `rescan()`. Для уже открытой старой сессии может
  понадобиться один `Project → Reload Current Project`, пока плагин не попал в
  её виртуальную ФС.

## Дополнения после code review

Ревью ветки выявило пять существенных сценариев; все исправлены и покрыты
тестами:

1. После перезагрузки страницы каталог с неопубликованными правками можно
   было только заменить скачиванием. Добавлено действие «Использовать
   каталог»: оно делает текущие файлы baseline (ревизия 0), после чего Emit
   публикует их. Автоматического восстановления набора загруженных пакетов
   по-прежнему нет.
2. Emit при известной более новой опубликованной ревизии теперь требует
   подтверждения и только затем повторяется с `force`; молчаливой
   перезаписи чужой ревизии нет.
3. Действия с одним пакетом защищены in-flight guard: повторный клик во время
   скачивания/удаления/Emit отклоняется, а не пишет в тот же staging-каталог.
4. 10-секундный опрос обновляет только серверные статусы. Хеширование файлов
   редактора выполняется при открытии панели, возврате фокуса, ручном
   «Обновить» и вокруг явных действий, поэтому не конкурирует с редактором.
5. Пакеты, опубликованные другим пользователем при открытом редакторе,
   добавляются в список из `GET /rooms/:roomId/game/packages`. Пакет с
   неизвестной версией показывается как «версия не указана».

Обновлённые проверки: frontend 6 файлов / 61 тест, `tsc --noEmit` и targeted
ESLint — чисто. Пункт 3 ручного checklist дополнен проверкой действия
«Использовать каталог»: после перезагрузки оставшиеся правки можно
опубликовать, не удаляя их.
