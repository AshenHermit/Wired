# Пример пакета: Wired Platformer

Готовый пример пакета комнаты: платформа, игрок с камерой и толканием, спавн
ящиков по ЛКМ и динамические ящики с сохранением.

Исходники лежат **вне** базового проекта `packages/server/godot_project/_wired`,
поэтому не попадают автоматически в редактор каждой комнаты. Пакет публикуется
в конкретную комнату через вкладку **Packages**.

## Состав

```
wired-platformer/
  wired_package.gd          # точка входа пакета, шесть регистраций
  static/platform.tscn      # StaticBody2D 640×32 + маркер спавна
  player/body.tscn          # CharacterBody2D, движение, прыжок, толкание
  player/camera.tscn        # Camera2D, следует только за своим игроком
  player/spawner.tscn       # ЛКМ → запрос на спавн ящика
  dynamic/crate.tscn        # RigidBody2D, импульс, сохранение состояния
  ui/custom_main.tscn       # кастомная main-сцена с собственной UI-разметкой
```

`wired_package.gd` регистрирует:

| Что | Путь | order | authority | Примечание |
|---|---|---|---|---|
| main-сцена | `ui/custom_main.tscn` | — | — | корень `WiredGameScene`, `world_viewport` → `Game/SubViewport` |
| статика | `static/platform.tscn` | 10 | server | платформа и маркер `wired_player_spawn` |
| игрок | `player/body.tscn` | 10 | server | движение, прыжок, толкание |
| игрок | `player/camera.tscn` | 20 | local | `local_only`, камера только у своего игрока |
| игрок | `player/spawner.tscn` | 30 | server | обработка запроса на ящик |
| динамика | `dynamic/crate.tscn` | — | server | тип `crate`, `persist`; лимит 8 и кулдаун 250 мс — параметры `player/spawner` |

Все пути относительны корня пакета, поэтому каталог можно копировать в
`res://packages/<slug>` без правок. Скрипты примера не объявляют `class_name` и не
используют RPC: вся сетевая логика идёт через ядро `_wired`.

## Своя main-сцена (необязательно)

Пакет может заменить штатный `Main/Game` своей сценой. Этот пример уже содержит
кастомную main scene в `ui/custom_main.tscn`, зарегистрированную в начале
`wired_package.gd`:

```gdscript
func register(_registry: WiredPackageRegistry) -> void:
	add_main_scene("ui/custom_main.tscn")
	# ... остальные регистрации
```

**Структура своей main-сцены:**

Корень сцены должен использовать скрипт `WiredGameScene` и указать
`world_viewport` — `SubViewport`, в который ядро переносит `StaticWorld`,
`DynamicWorld` и `Players`. В `custom_main.tscn`:

```
CustomMain (Node) [script: WiredGameScene]
  ├─ Game (SubViewportContainer)
  │  └─ SubViewport [world_viewport]   # пустой: сервисы добавит ядро
  └─ UI (CanvasLayer)
     └─ Background, Margin, VBox, Status, Hint, Log
```

`world_viewport` намеренно пустой. Ядро само переносит в него живые
`StaticWorld`, `DynamicWorld` и `Players` вместе со спавнерами. Не копируйте эти
узлы из `main.tscn`: при совпадении имён Godot переименует живые сервисы в
недетерминированные `@Node@N`, и сетевые пути игроков перестанут совпадать
между сервером и клиентом (пропадает движение и обновление мира).

Остальные `SubViewport` (миникарта, превью) свободны: ядро использует только
`world_viewport`.

**UI и интерактивность:**

Кастомный UI сохраняет свой `mouse_filter`: кнопки и панели кликаются. Штатный
`Main/UI` по-прежнему игнорирует мышь, чтобы клики доходили до игрового
viewport.

**Применение и замена:**

Побеждает первая main-сцена в порядке реестра (package id, `order`, порядок
регистраций). Если сцена битая, `world_viewport` не задан или внутри него уже
есть зарезервированный узел (`StaticWorld`, `DynamicWorld`, `Players`), комната
остаётся на штатном `Game`, а в лог пишется
`WIRED_MAIN_SCENE_INVALID ... reason=...`. Ошибка не фатальна: после исправления
сцены достаточно опубликовать новую ревизию. При новой ревизии пакета main-сцена
пересобирается, поэтому её UI-состояние сбрасывается; живые игроки и
динамические сущности сохраняются.

## Как опубликовать пакет в комнате

Для ручной проверки нужны собранный Web export (`pnpm export:game`), запущенные
backend и frontend и открытая комната.

1. Откройте вкладку **Packages** (панель «Пакеты комнаты»).
2. Нажмите **Создать пакет** и заполните модальное окно: «Имя пакета»
   (например, `Wired Platformer`), «Версию» (например, `0.1.0`) и **Slug**
   (например, `wired_platformer`; строчные латинские буквы, цифры и `_`).
   После создания в карточке пакета появится slug — `#<slug>`; в редакторе
   появится пустой каталог `packages/<slug>`.
3. Скопируйте содержимое
   `packages/server/godot_project/examples/wired-platformer/` в
   `packages/<slug>/` в файловой системе редактора (вкладка **FileSystem**),
   сохранив структуру каталогов: `wired_package.gd`, `static/`, `player/`,
   `dynamic/`.
   - Если пакет уже публиковался, сначала нажмите **Скачать в редактор**, затем
     замените файлы примером. Кнопка **Убрать из редактора** удаляет только
     каталог этого пакета.
4. Нажмите **Emit** в карточке пакета. Панель покажет опубликованную ревизию;
   runtime комнаты применит её и разошлёт клиентам.
5. Откройте вкладку **Game** в двух окнах или вкладках браузера (два клиента
   одной комнаты). Первый запуск runtime и синхронизация пакетов занимают
   несколько секунд.

Первый клиент запускает серверный runtime комнаты; второй подключается к нему.
Если игроки уже были в игре во время Emit, статика применится сразу, а для
компонентов игрока (тело, камера, спавнер) нужен reconnect/повторный вход.

## Управление

| Действие | Клавиши |
|---|---|
| движение | A / D или ← / → |
| вверх / вниз | W / S или ↑ / ↓ |
| прыжок | Space |
| спавн ящика | ЛКМ |

## Что должно работать

- Платформа 640×32 видна обоим клиентам; сцена содержит `Marker2D` `Spawn`
  в группе `wired_player_spawn`.
- У каждого клиента свой игрок, камера следует только за своим и не
  перехватывает вид у второго.
- Движение и прыжок реплицируются: второй клиент видит те же перемещения.
- Игроки толкают друг друга, толчок не телепортирует тело и плавно затухает.
- ЛКМ спавнит ящик рядом с игроком в сторону курсора; импульс и полёт видны
  обоим клиентам.
- Ящик сталкивается с платформой и игроками, лимит — 8 живых ящиков на игрока,
  кулдаун — 250 мс.
- Ящики сохраняются в `state.json` и восстанавливаются после перезапуска
  runtime комнаты (импульс при восстановлении не повторяется).
- Поздно подключившийся клиент получает уже существующих игроков со всеми
  компонентами и текущие ящики ровно один раз: ядро отправляет авторитетный
  снимок после готовности пакетов и не полагается на один лишь spawn-replay.
- Ящики с `persist: false` (если пакет так зарегистрирует тип) видны в текущем
  мире и в снимке для позднего клиента, но не попадают в `state.json`.

## Ограничения

- Горячая замена пакета пересобирает статику, но не пересобирает уже
  заспавненных игроков: для новых компонентов нужен reconnect. Живые игроки и
  динамические сущности при этом не заменяются `PackageReloader`.
- `MultiplayerSpawner`/`MultiplayerSynchronizer` в Godot 4.7 реплицируют данные
  на транспортном уровне и не фильтруются ticket-аутентификацией. Игровые RPC
  закрыты, окно до `cli_hello` ограничено таймаутом; полностью убрать это
  ограничение можно только заменой spawner/synchronizer на авторитетные RPC
  (отдельная задача).

## Если что-то не работает

- **Emit недоступен.** Пакет не загружен в редактор: нажмите **Скачать в
  редактор** (для нового пустого пакета каталог создаётся сразу).
- **Каталога `packages/<slug>` не видно во вкладке FileSystem.** Сохраните сцены и
  выполните Project → Reload Current Project. Перезагрузка страницы сбрасывает
  набор загруженных пакетов.
- **Вкладка Game сообщает об отсутствии сборки.** Соберите Web export командой
  `pnpm export:game` и обновите страницу.
- **Ящики не спавнятся.** Проверьте параметры компонента `player/spawner`
  (`max_per_player = 8`, `cooldown_ms = 250`); запрос принимается только от
  локального игрока. Это политика пакета, а не опции динамической регистрации.
- **После Emit пропали камера или управление.** Переподключитесь к комнате:
  компоненты игрока собираются при спавне, а не на лету.
- **В консоли `WIRED_PACKAGE_INSTANTIATE_FAILED .../static/platform.tscn` (или
  `player/body.tscn`).** Файлы опубликованы плоско, без подкаталогов. Верните
  структуру: `platform.tscn` → `static/`, файлы тела/камеры/спавнера →
  `player/`, файлы ящика → `dynamic/`; `wired_package.gd` остаётся в корне.
  Затем нажмите **Emit** ещё раз. Регистрация в `wired_package.gd` ссылается
  именно на эти пути.
